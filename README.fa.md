# راهنمای فارسی پروژهٔ پارسیان

این پروژه فعلاً فقط زیرساخت اجرای Django، Tailwind CSS و جاوااسکریپت ساده را دارد. هیچ صفحهٔ نمایشی، مدل اختصاصی، فرم، منوی آماده یا منطق کسب‌وکار در آن پیاده‌سازی نشده است. صفحهٔ اصلی عمداً خالی است؛ فقط اسکلت HTML و اتصال به CSS و JavaScript را نگه می‌دارد.

## اجرای پروژه با یک دستور

از ریشهٔ پروژه اجرا کنید:

```bash
python3 run.py
```

این فایل به‌ترتیب:

1. محیط پایتون، ابزارهای فرانت‌اند و آزاد بودن پورت را بررسی می‌کند.
2. بک‌اند Django را روی `127.0.0.1:8000` اجرا می‌کند و منتظر پاسخ موفق می‌ماند.
3. CSS را می‌سازد و Tailwind را در حالت watch اجرا می‌کند؛ پس از آماده شدن خروجی ادامه می‌دهد.
4. نشانی پروژه را در مرورگر پیش‌فرض باز می‌کند.

برای بستن بک‌اند و فرانت‌اند با هم، در همان ترمینال `Ctrl+C` بزنید. اگر یکی از فرایندها دچار خطا شود، فایل اجراکننده بقیه را هم متوقف می‌کند. اجرای این فایل به فعال کردن دستی `.venv` نیاز ندارد و مسیرها را از محل خود فایل پیدا می‌کند.

گزینه‌های اختیاری:

```bash
python3 run.py --port 8001
python3 run.py --no-browser
```

فرانت‌اند این پروژه سرور جداگانه ندارد: Tailwind فقط CSS را می‌سازد و Django قالب HTML، CSS و JavaScript را در محیط توسعه ارائه می‌کند. باز شدن مرورگر به‌معنی باز شدن یک صفحهٔ خالی است. بازخوانی خودکار مرورگر تنظیم نشده؛ پس از تغییر فایل‌های فرانت‌اند، صفحه را دستی تازه‌سازی کنید. Django تغییر فایل‌های پایتون را تشخیص می‌دهد و خودش دوباره اجرا می‌شود.

│   │   └── wsgi.py
│   ├── .env
│   ├── .env.example

│   ├── staticfiles/
│   ├── manage.py

پوشه‌ها و فایل‌های محلی مثل `.venv`، `node_modules`، `.env`، `db.sqlite3`، `staticfiles` و CSS ساخته‌شده داخل Git ذخیره نمی‌شوند. ساختار بالا وضعیت محیط محلی را هم نشان می‌دهد؛ همهٔ این موارد در یک نسخهٔ تازهٔ مخزن وجود ندارند.

### بخش بک‌اند

| مسیر | کاربرد |
| --- | --- |
| `backend/` | فایل‌های پایتون، تنظیمات سرور و پایگاه داده |
| `backend/config/` | بستهٔ اصلی پروژهٔ Django |
| `config/__init__.py` | فایل خالی برای تعریف بستهٔ پایتونی |
| `config/settings.py` | تنظیم پایگاه داده، محیط، امنیت، قالب‌ها و فایل‌های استاتیک؛ مسیر فرانت‌اند از محل همین فایل محاسبه می‌شود |
| `config/urls.py` | مسیر `/` برای قالب خالی با `TemplateView` خود Django و مسیر `/admin/` برای پنل مدیریت استاندارد Django |
| `config/asgi.py` | نقطهٔ ورود برای سرورهایی که رابط ASGI را پشتیبانی می‌کنند |
| `config/wsgi.py` | نقطهٔ ورود برای سرورهایی که رابط WSGI را پشتیبانی می‌کنند |
| `backend/manage.py` | ابزار خط فرمان Django برای بررسی پروژه، اجرای سرور، migration و کارهای مدیریتی |
| `backend/requirements.txt` | نسخهٔ دقیق وابستگی‌های پایتون برای نصب تکرارپذیر |
| `backend/.env` | تنظیمات محلی و کلید محرمانه؛ نباید وارد مخزن شود |
| `backend/.env.example` | نمونهٔ تنظیمات بدون کلید واقعی برای راه‌اندازی محیط تازه |
| `backend/db.sqlite3` | فایل پایگاه دادهٔ محلی؛ دیتابیس قبلی حفظ شده است |
| `backend/staticfiles/` | خروجی `collectstatic` برای ارائهٔ فایل‌های استاتیک هنگام استقرار؛ محل ویرایش فایل‌های فرانت‌اند نیست |

فعلاً اپلیکیشن اختصاصی Django وجود ندارد. اپ `core` و کد نمونهٔ قبلی حذف شده‌اند. قابلیت‌های استاندارد Django مانند مدیریت، کاربران، نشست‌ها، پیام‌ها و staticfiles نگه داشته شده‌اند. migrationهای همین قابلیت‌ها قبلاً روی SQLite اجرا شده‌اند. هنگام اضافه شدن قابلیت واقعی، اپ Django و migration مربوط به آن را داخل `backend/` ایجاد کنید.

### بخش فرانت‌اند

| مسیر | کاربرد |
| --- | --- |
| `frontend/` | تمام فایل‌های رابط مرورگر و ابزار ساخت CSS |
| `frontend/assets/` | فایل‌های ورودی ابزار ساخت که مستقیماً به مرورگر داده نمی‌شوند |
| `frontend/assets/css/input.css` | ورودی Tailwind v4؛ شامل import و مسیر جست‌وجوی کلاس‌ها در قالب‌ها و JavaScript |
| `frontend/templates/` | قالب‌های HTML که Django پردازش می‌کند |
| `frontend/templates/base.html` | اسکلت حداقلی HTML5 با زبان فارسی، جهت راست‌به‌چپ و لینک CSS و ماژول JavaScript؛ بدنه خالی است |
| `frontend/static/` | فایل‌هایی که در مرورگر دریافت می‌شوند |
| `frontend/static/css/` | محل خروجی CSS ساخته‌شده |
| `frontend/static/css/app.css` | خروجی خودکار Tailwind؛ ویرایش آن با ساخت بعدی از بین می‌رود |
| `frontend/static/js/app.js` | نقطهٔ ورود JavaScript به‌صورت ES module؛ فعلاً خالی است |
| `frontend/static/images/` | محل تصاویر آیندهٔ پروژه |
| `.gitkeep` | فایل خالی برای نگهداری پوشهٔ بدون فایل در Git |
| `frontend/package.json` | وابستگی‌های فرانت‌اند و دستورهای build و watch |
| `frontend/package-lock.json` | نسخهٔ دقیق وابستگی‌های مستقیم و غیرمستقیم npm |
| `frontend/node_modules/` | بسته‌های نصب‌شدهٔ npm؛ با `npm ci` دوباره ساخته می‌شود |

در Tailwind v4 تنظیم import و مسیرهای جست‌وجو داخل CSS انجام شده است؛ برای این ساختار به `tailwind.config.js` یا تنظیم PostCSS نیاز نیست. کلاس‌ها باید به‌شکل کامل در فایل‌ها نوشته شوند تا ابزار ساخت بتواند آن‌ها را پیدا کند. اگر بعداً قالب‌ها را جای دیگری قرار دادید، مسیر `@source` مناسب را هم به `input.css` اضافه کنید.

### فایل‌های ریشه و پوشه‌های خودکار

| مسیر | کاربرد |
| --- | --- |
| `run.py` | اجرای ترتیبی بک‌اند و ابزار فرانت‌اند، باز کردن مرورگر و مدیریت توقف فرایندها؛ فقط از کتابخانهٔ استاندارد پایتون استفاده می‌کند |
| `.venv/` | محیط مجازی پایتون؛ بسته‌های بک‌اند در این محیط نصب می‌شوند |

| `.gitignore` | جلوگیری از ثبت وابستگی‌ها، رمزها، دیتابیس محلی، کش و خروجی‌های تولیدشده |

## نصب در محیط تازه

محیط فعلی نصب و آماده شده است. برای یک نسخهٔ تازه از پروژه، پس از نصب Python و Node.js، از ریشه اجرا کنید:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
npm --prefix frontend ci
cp backend/.env.example backend/.env
python -c "from secrets import token_urlsafe; from dotenv import set_key; set_key('backend/.env', 'DJANGO_SECRET_KEY', token_urlsafe(64))"
python backend/manage.py migrate
python run.py
```

دستور `source` برای macOS و Linux است. در PowerShell ویندوز، فعال‌سازی محیط با `.venv\Scripts\Activate.ps1` انجام می‌شود. فایل `.env` موجود را در اجرای روزمره جایگزین نکنید و کلیدش را دوباره نسازید.

## تنظیمات محیط

| متغیر | کاربرد |
| --- | --- |
| `DJANGO_SECRET_KEY` | کلید محرمانهٔ الزامی؛ مقدار واقعی فقط در محیط یا `.env` قرار می‌گیرد |
| `DJANGO_DEBUG` | در توسعه `true`؛ اگر تنظیم نشود، مقدار پیش‌فرض خاموش است |
| `DJANGO_ALLOWED_HOSTS` | میزبان‌های مجاز با کاما؛ برای اجرای محلی شامل `localhost` و `127.0.0.1` است |
| `DJANGO_TIME_ZONE` | منطقهٔ زمانی؛ پیش‌فرض `Asia/Tehran` |
| `DB_ENGINE` | مقدار `sqlite` برای توسعه یا `postgresql` برای اتصال آینده |
| `DB_NAME`، `DB_USER`، `DB_PASSWORD` | نام پایگاه داده و اطلاعات دسترسی PostgreSQL |
| `DB_HOST`، `DB_PORT` | میزبان و پورت PostgreSQL |
| `DB_SSLMODE` | تنظیم SSL اتصال PostgreSQL مطابق نیاز سرویس میزبان |

PostgreSQL و درایورش فعلاً نصب نیستند. برای استفاده در آینده باید سرویس آن فراهم شود، درایور `psycopg[binary]` نصب و به وابستگی‌ها اضافه شود، متغیرها تنظیم شوند و migrationها روی پایگاه مقصد اجرا شوند. تغییر اتصال، داده‌های SQLite را خودکار منتقل نمی‌کند.

## دستورهای مستقل و بررسی سلامت

همهٔ دستورهای زیر از ریشهٔ پروژه هستند. پیش از دستورهای `python`، محیط مجازی را فعال کنید.

```bash
# اجرای مستقل بک‌اند
python backend/manage.py runserver

# اجرای مستقل Tailwind در حالت watch
npm --prefix frontend run watch:css

# ساخت CSS فشرده
npm --prefix frontend run build:css

# بررسی تنظیمات و وضعیت migrationها
python backend/manage.py check
python backend/manage.py migrate --check

# بررسی وابستگی‌های پایتون
python -m pip check

# بررسی نحو JavaScript
node --check frontend/static/js/app.js

# جمع‌آوری فایل‌های استاتیک برای استقرار
python backend/manage.py collectstatic --noinput
```

فعلاً تست اختصاصی برنامه وجود ندارد، چون قابلیت اختصاصی پیاده‌سازی نشده است. `run.py` ابزار توسعه است؛ استقرار واقعی به سرور WSGI/ASGI، ارائهٔ فایل‌های استاتیک، تنظیمات امنیتی و HTTPS متناسب با میزبان نیاز دارد.
